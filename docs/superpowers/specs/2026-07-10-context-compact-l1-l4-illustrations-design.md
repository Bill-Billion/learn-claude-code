# L1-L4 草稿纸压缩插图设计

## 目标

为 `s08_context_compact` 绘制四张更具象的教学插图。四张图采用同一张工作桌上的草稿纸作为主角，用实物整理动作解释四级压缩机制，让初学者在不阅读代码的情况下也能先看懂“发生了什么”。

旧版流程图保留，新版以 `-v2.svg` 命名，便于并排比较后再决定是否替换文章插图。

## 共同视觉语言

- 画布统一为 `760 x 440`，白底、黑灰线稿，圆角不超过 6px。
- 沿用现有配色：正文 `#1a1a1a`、辅助线 `#d0d0d0`、次要文字 `#888888`、强调色 `#22c55e`。
- 绿色只表示仍被保留、能够找回的信息，以及压缩动作的方向；不用于装饰。
- 每张图保持“整理前、手部动作、整理后”的阅读顺序，但减少代码框和英文函数名。
- 标题说明机制名，画面负责解释动作；底部只保留一句通俗结论。

## 四张构图

### L1：把大结果搬出草稿纸

草稿纸上压着一卷过长的工具输出。整理动作把长纸卷抽出，放入标有 `.task_outputs/` 的档案盒；草稿纸原处留下绿色便签，便签上只有文件路径和一小段预览。重点表达“完整内容没有消失，只是搬到别处”。

### L2：剪掉对话中间段

用一条横向折叠的长纸带代表完整消息历史。纸带左端是原始任务，右端是最新进度，中间堆着旧过程。剪刀沿两条虚线裁掉中段，再用一条写着 `[snipped ... messages]` 的窄纸条连接两端。裁切位置不能拆开 `tool_use` 与 `tool_result` 配对。

### L3：擦短较早的工具结果

桌面依时间顺序摆放五张结果纸。较早的 #1、#2 被橡皮擦成两张小占位便签；最近的 #3、#4、#5 保持完整，并由绿色回形针圈在一起。消息位置仍然存在，只替换旧结果正文。此构图严格对应 `KEEP_RECENT = 3`。

### L4：把整本历史写成工作摘要

一摞厚历史先用装订夹收入 `transcript` 档案，再经过“阅读、划重点、重写”的漏斗式动作，变成桌面上的一页摘要。摘要明确保留目标、约束、发现、文件和下一步；漏斗旁散落少量灰色字迹，提示这是有损压缩，因此最后才使用。

## 准确性边界

- L1 表达单条或同批工具结果超过预算后按大小持久化，不暗示所有工具结果都会落盘。
- L2 表达裁消息数量，保留安全头尾，不暗示对中间内容进行了语义总结。
- L3 表达替换较早且较长的 `tool_result.content`，最近三条不变，不误画成删除整条消息。
- L4 同时表达“完整 transcript 已落盘”和“当前上下文被摘要替换”，并明确摘要有损。

## 交付与验证

- 输出四个独立 SVG，不覆盖旧稿，也暂不插入文章。
- 使用 `xmllint --noout` 验证 XML。
- 渲染为 PNG 后逐张检查文字溢出、线条遮挡、动作方向及四图一致性。
